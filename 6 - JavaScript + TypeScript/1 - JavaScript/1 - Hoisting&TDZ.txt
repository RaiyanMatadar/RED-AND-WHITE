------What is JavaScript Hoisting.
Hoisting refers to the behavior where JavaScript moves the declarations of variables, functions, and 
classes to the top of their scope during the compilation phase. This can sometimes lead to surprising 
results, especially when using var, let, const, or function expressions.

	Quick Diagram of it 

     |--> x = 1;
     |    alert("x = " + x);
     |--  var x;

-Hoisting applies to variable and function declarations.
-Initializations are not hoisted; they are only declarations.
-'var' variables are hoisted with undefined, while 'let' and 'const' are hoisted but remain in the 
Temporal Dead Zone until initialized.

--Temporal Dead Zone--
If you try to use a let or const before they are initialized, JS gives an error.
Why? Because they are in the Temporal Dead Zone — JS knows the variable exists but doesn’t 
let you use it yet, so you don’t create bugs like what happened with var.

|--> TDZ starts for x (x exists in memory but uninitialized)
|
|--> alert(x)  // ReferenceError
|
|--> let x;    // x declared (still uninitialized)
|
|--> x = 1;    // x initialized, TDZ ends
|
|--> alert(x)  // Works now, outputs 1  

TDZ is the period from the start of the scope until the let or const is initialized.
Accessing the variable anywhere in the TDZ gives a ReferenceError.
