# SQL Constraints

Constraints are rules applied to columns in a table to ensure the accuracy and reliability of data. If any data action violates a constraint, the action is aborted. They can be added when creating a table or later using `ALTER TABLE`.

---

## 1. NOT NULL

Ensures a column **cannot be left empty**. Every row must have a value for this column.

```sql
CREATE TABLE employees (
    employee_id INT NOT NULL,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50)
);
```

Adding it to an existing column:
```sql
ALTER TABLE employees
MODIFY first_name VARCHAR(50) NOT NULL;
```

---

## 2. UNIQUE

Ensures every value in a column is different — no two rows can have the same value in that column.

```sql
CREATE TABLE employees (
    employee_id INT NOT NULL UNIQUE,
    email VARCHAR(100) UNIQUE
);
```

> 💡 A table can have **multiple** UNIQUE columns, but only **one** PRIMARY KEY.

## 3. PRIMARY KEY

A PRIMARY KEY **uniquely identifies each row** in a table. It's just NOT NULL + UNIQUE combined.

**Rule: A table can only have ONE primary key.**

So this won't work:

```sql
--  WRONG — two PRIMARY KEYs on separate columns
CREATE TABLE employees (
    employee_id    INT PRIMARY KEY,
    employee_email INT PRIMARY KEY  -- ERROR: only one primary key allowed
);
```

SQL will throw an error. You simply can't declare `PRIMARY KEY` twice like that.

---

**So what if you need two columns to act as the identifier together?**

Use a **Composite Primary Key** — one primary key made of two columns combined.

```sql
-- CORRECT — one primary key using two columns together
CREATE TABLE enrollments (
    student_id INT,
    course_id  INT,
    PRIMARY KEY (student_id, course_id)
);
```

**Why does this make sense here?**

A student can enroll in many courses. A course can have many students. But the same student can't enroll in the same course twice. So the *combination* of `student_id + course_id` is unique — that's your primary key.

| student_id | course_id | Valid? |
|---|---|---|
| 1 | 101 | ✅ |
| 1 | 102 | ✅ (same student, different course) |
| 2 | 101 | ✅ (different student, same course) |
| 1 | 101 | ❌ duplicate — blocked |

## 4. FOREIGN KEY

A FOREIGN KEY links a column in one table to the PRIMARY KEY in another table, ensuring that values in the foreign key column match a valid record in the referenced table.

```sql
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

This means you **cannot insert an order** with a `customer_id` that doesn't exist in the `customers` table. It keeps the relationship between tables valid.

---

## 5. CHECK

The CHECK constraint allows you to specify a condition that data must satisfy before it can be inserted into the table.

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    hourly_pay DECIMAL(5,2) CHECK (hourly_pay >= 10.00),
    age INT CHECK (age >= 18)
);
```

You can also name your CHECK constraint for easier reference later:

```sql
ALTER TABLE employees
ADD CONSTRAINT chk_pay CHECK (hourly_pay >= 10.00);
```

---

## 6. DEFAULT

The DEFAULT constraint sets an automatic value for a column when no value is provided during insertion.

```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    hire_date DATE DEFAULT (CURRENT_DATE),
    country VARCHAR(50) DEFAULT 'India'
);
```

So if you insert a row without specifying `country`, it automatically becomes `'India'`.

---

## 7. INDEX *(not a constraint, but often grouped with them)*

An INDEX speeds up data retrieval when querying by a specific column. Users cannot see indexes — they are used internally by the SQL engine to speed up searches.

```sql
CREATE INDEX idx_last_name
ON employees(last_name);
```

Unique index (no duplicate values allowed):
```sql
CREATE UNIQUE INDEX idx_email
ON employees(email);
```

> ⚠️ Indexes speed up **reads** but can slow down **writes** (INSERT/UPDATE/DELETE), so don't overuse them.

## All Together — Example Table

```sql
CREATE TABLE employees (
    employee_id   INT           PRIMARY KEY,         -- NOT NULL + UNIQUE
    first_name    VARCHAR(50)   NOT NULL,             -- required field
    last_name     VARCHAR(50)   NOT NULL,
    email         VARCHAR(100)  UNIQUE,               -- no duplicates
    hourly_pay    DECIMAL(5,2)  CHECK (hourly_pay >= 10.00), -- must be >= 10
    department_id INT           DEFAULT 1,            -- defaults to dept 1
    FOREIGN KEY (department_id) REFERENCES departments(department_id)
);
```

## Quick Reference Table

| Constraint | Purpose |
|---|---|
| `NOT NULL` | Column must always have a value |
| `UNIQUE` | All values in the column must be different |
| `PRIMARY KEY` | Uniquely identifies each row (NOT NULL + UNIQUE) |
| `FOREIGN KEY` | Links to the PRIMARY KEY of another table |
| `CHECK` | Value must satisfy a condition |
| `DEFAULT` | Assigns a fallback value if none is provided |
| `INDEX` | Speeds up search/query performance |
