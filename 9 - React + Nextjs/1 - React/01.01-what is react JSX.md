# React `createElement` Notes

---

## What is it?

`createElement` is the **old/manual way** to write React UI — before JSX existed.

JSX is just a shortcut. Babel (a compiler) turns your JSX into `createElement` calls automatically.

So these two are **exactly the same thing:**

```jsx
// JSX (modern way)
<h1>Hello</h1>

// createElement (what JSX compiles to)
createElement("h1", null, "Hello")
```

---

## The Syntax

```js
createElement(type, props, children)
```

It takes **3 arguments:**

| Argument | What it is | Example |
|---|---|---|
| `type` | The HTML tag or component | `"h1"`, `"div"`, `MyComponent` |
| `props` | Attributes / data | `{ className: "box" }` or `null` |
| `children` | What goes inside | `"Hello"`, another element |

---

## Simple Examples

**No props, just text inside:**
```js
createElement("h1", null, "Hello World")
// same as: <h1>Hello World</h1>
```

**With props:**
```js
createElement("h1", { className: "title" }, "Hello World")
// same as: <h1 className="title">Hello World</h1>
```

**Element inside an element:**
```js
createElement("div", null,
  createElement("h1", null, "Title"),
  createElement("p",  null, "Some text")
)

// same as:
// <div>
//   <h1>Title</h1>
//   <p>Some text</p>
// </div>
```

> You can pass as many children as you want — just keep adding arguments after `props`.

---

## What Does It Return?

`createElement` does NOT create a real DOM element.

It returns a **plain JS object** — a lightweight description. React reads this object later and figures out what to put on screen.

```js
// This object is what React works with internally
{
  type:  "h1",
  props: { children: "Hello World" },
  key:   null,
  ref:   null
}
```

This object is called a **React element** (also called a virtual DOM node).

---

## How The Full Flow Works

```
createRoot(domNode)   →  attaches React to a real HTML element
createElement(...)    →  creates a cheap JS object (the description)
root.render(element)  →  React reads the object, then updates the real DOM
```

React only touches the real DOM at step 3. Steps 1 and 2 are just JS — fast and cheap.

---

## Your Code Explained Line by Line

```js
import { createElement } from "react"       // import the function
import { createRoot } from "react-dom/client" // import the renderer

const root = createRoot(document.getElementById("root"))
// 👆 Tell React: "manage the <div id="root"> in my HTML"

const reactElement = createElement("h1", null, "Hello from createElement!")
// 👆 Create a JS object describing an <h1> with text inside
//    null = no props/attributes needed

console.log(reactElement)
// 👆 You'll see the plain object React uses internally

root.render(reactElement)
// 👆 Now React actually builds the real DOM node and puts it on screen
```

## Common Mistakes

**HTML tags must be lowercase strings:**
```js
createElement("h1", ...)  // ✅ correct — HTML tag
createElement("H1", ...)  // ❌ wrong  — React thinks H1 is a component
```

**Use `className`, not `class`:**
```js
createElement("div", { className: "box" })  // ✅
createElement("div", { class: "box" })      // ❌ class is a reserved JS keyword
```

**No props? Pass `null`:**
```js
createElement("h1", null, "Hello")  // ✅ clean
createElement("h1", {}, "Hello")    // ✅ also works, just less clean
```

---

## Quick Summary

- `createElement` = the real thing behind every JSX tag
- It just returns a JS object — not a real DOM node
- `root.render()` is the step that actually touches the DOM
- JSX is just a nicer way to write `createElement` calls
